## 铁律（违反即不合格）

> **生成 .docx 报告必须严格按照模板文件 `templates/数字金融洞察格式模板参考0413.docx` 的格式和风格，不得自由发挥。**

写作阶段和生成阶段都必须遵守此铁律。做不到等于报告不合格。

## 前置加载（必做，不可跳过）

在开始任何撰写工作之前，**必须**依次阅读以下参考文件：

1. `guides/writing-guide.md` — 写作规范（风格模板、八条宪法、小组件方法）。**先读这个，否则不知道怎么写。**
2. `templates/数字金融洞察格式模板参考0413.docx` — 格式模板，理解排版要求（字体、字号、颜色、页边距等）。

不阅读这两份文件不得开始撰写。

## 双路径工作流

### 路径A：完整撰写（讨论→写作→转换）

当用户提出一个主题（非 Markdown 文件）时，使用完整路径：

1. **加载参考文件**：按"前置加载"步骤执行
2. **讨论确定核心信息**：与用户讨论核心论点、读者受众、关键材料
3. **选择风格**：按 `writing-guide.md` 的决策树确定风格（A/B/C）
4. **输出大纲并确认**：写出结构骨架让用户确认
5. **撰写全文**：严格按选定风格的 Prompt 模板和小组件方法撰写，所有格式规范（字体、字号、颜色、行距、编号）必须与模板文件一致
6. **生成 .docx**：按"快速路径"的步骤调用转换脚本

风格选择参考：

- **A 理论建构型**：外部提出了颠覆性框架/理论（如Thompson推理转移、华韬定律）
- **B 事件驱动型**：行业发生重大事件/趋势（如AI支付协议发布、Token消费爆发）
- **C 同业深研型**：同业做出了值得研究的实践（如宁波银行、摩根大通、Palantir）

### 路径B：快速转换（仅格式转换）

当用户直接提供 Markdown 文件时，使用快速路径：

1. 用户提供 Markdown 格式的文章内容（或指定 .md 文件路径）
2. 技能调用 `scripts/gen_insight_doc.py` 将其转换为符合格式要求的 .docx 文件
3. 输出文件保存到用户当前工作目录

⚠️ 转换时必须使用模板文件 `templates/数字金融洞察格式模板参考0413.docx`，脚本会自动引用该模板。确保模板文件存在且未被修改。

### 路径C：质量检查（生成后必跑）

生成 .docx 后**必须**运行格式质量检查。标准流程为两步：

```bash
# 第一步：生成
cd <skill根目录> && python3 scripts/gen_insight_doc.py <input.md> <output.docx> [issue_year] [issue_number] [issue_date]

# 第二步：自动修复 + 验证（必须执行，不可跳过）
python3 scripts/check_docx_quality.py <output.docx> --fix
```

检查并自动修复的项目：

- **字体修正**：根据段落模式（title/heading1/heading2/body）自动推断并修正错误的中英文字体
- **引号规范化**：ASCII 双引号 `"`、英文智能引号 `""` 等 → 统一转中文引号 `""`
- **特殊字符清除**：连续星号 `****`、Markdown 加粗残留 `**`、乱码字符 `�`、零宽字符

⚠️ **生成流程铁律**：生成 → `--fix` → 确认通过。三步缺一不可。如果检查不通过，必须先修复 Markdown 源文件或 gen_insight_doc.py 脚本，再重新生成。

## 调用方式

```bash
cd <skill根目录> && python3 scripts/gen_insight_doc.py <input.md> <output.docx> [issue_year] [issue_number] [issue_date]
```

参数说明：

- `input.md`：Markdown 源文件路径
- `output.docx`：输出 Word 文件路径
- `issue_year`：期号年份，如 `2026`
- `issue_number`：期号序号，如 `42`
- `issue_date`：日期文字，如 `2026年5月11日`

示例：

```bash
python3 scripts/gen_insight_doc.py report.md 数字金融洞察_输出.docx 2026 5 "2026年5月11日"
```

## 格式规范

### 页面设置

- 页边距：上下 2.54cm，左右 3.18cm
- 纸张：A4

### 文档头部（蓝色抬头）

文档顶部包含一个蓝色抬头区域，由模板文件 P0 段落提供，包含 3 个浮动形状：

1. **文本框"数字金融发展办公室"** — 黑体 12pt，蓝色(#4472C4/#0099DE)，右上角定位
2. **文本框"内部版"** — 仿宋 14pt，白色字，居中定位
3. **组合形状（蓝色横幅 #0099DE 背景）** — 包含：
   - "数字 金融·洞察" — 华文行楷 28pt，白色，居中
   - "【YYYY】第N期" — 方正楷体 14pt，#0099DE
   - "YYYY年M月D日" — 方正楷体 14pt，#0099DE

### 行距与对齐

- 全文行距：1.2 倍
- 对齐方式：两端对齐
- 全文首行缩进 2 字符（文档大标题和"内容提供"行除外）

### 标题与正文格式

| 元素       | 中文字体       | 西文字体        | 字号       | 加粗 | 颜色          | 对齐     |
| ---------- | -------------- | --------------- | ---------- | ---- | ------------- | -------- |
| 文档大标题 | 方正小标宋简体 | Times New Roman | 二号(22pt) | 是   | 蓝色(#2F78DA) | 居中     |
| 内容提供行 | 方正仿宋       | Times New Roman | 三号(16pt) | 是   | 黑色          | 居中     |
| 一级标题   | 方正黑体       | Times New Roman | 三号(16pt) | 否   | 黑色          | 两端对齐 |
| 二级标题   | 方正楷体       | Times New Roman | 三号(16pt) | 否   | 黑色          | 两端对齐 |
| 三级标题   | 方正仿宋       | Times New Roman | 三号(16pt) | 否   | 黑色          | 两端对齐 |
| 四级标题   | 方正仿宋       | Times New Roman | 三号(16pt) | 否   | 黑色          | 两端对齐 |
| 正文       | 方正仿宋       | Times New Roman | 三号(16pt) | 否   | 黑色          | 两端对齐 |

### 标题编号规则

- 一级标题：一、二、三、... （手工输入）
- 二级标题：（一）（二）（三）... （手工输入）
- 三级标题：1. 2. 3. ... （手工输入）
- 四级标题：（1）（2）（3）... （手工输入）

### Markdown 映射规则

- `# 标题` → 文档大标题
- `## 一级标题` 或 `一、...` → 一级标题
- `### 二级标题` 或 `（一）...` → 二级标题
- `#### 三级标题` 或 `1. ...` → 三级标题
- `（1）...` → 四级标题
- `内容提供：...` → 内容提供行

### 引号规范

- 中文语境下的引号必须使用中文引号：`""`（双引号）、`''`（单引号）
- 英文双引号 `"` → 中文双引号 `""`：解析时自动成对转换，奇数位 `"` → `"`，偶数位 `"` → `"`
- 英文单引号 `'` → 中文单引号 `''`：仅转换成对使用的引号，缩写中的撇号（如 don't、it's、owners'）保留不变
- 源 Markdown 中无论使用英文还是中文引号，脚本均会自动规范化为中文引号
